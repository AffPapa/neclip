# NeClip 1.11.0 / build 18 — локальный аудит

Дата: 7 сентября 2026. Исходная точка:
`0a5357e943bc7bb318bd0926d35746c6dcddc55b`.

**Статус: локальный кандидат, не публичный релиз.** Доступная для скачивания
версия остаётся **1.10.0/build 17**. Установленное приложение и рабочая база
пользователя в этом проходе не заменяются. Этот документ не подтверждает
нотарификацию, публикацию, установку или готовность к ним.

## Задача и порядок работы

Сделать NeClip незаметным помощником: меньше повторной работы, понятная версия
запущенной копии, проверка обновлений только по запросу. Перед изменениями
проведены три независимых read-only аудита: продуктовый, производительности и
интерфейса обновлений. План и границы:
`artifacts/neclip/looper-goals/20260907-invisible-version/plan.md`.

Основной агент прочитал рекомендации OpenAI `swiftui-performance-audit`
в режиме read-only discovery, включая материалы по профилированию и отчётности.
Навык не устанавливался как зависимость приложения; сторонние скрипты из него
не стали частью сборки. Новых библиотек в NeClip не добавлено.

## Исследование 15 аналогов

[Матрица сценариев и решений](RESEARCH-1.11.0-INVISIBLE-2026-09-07.md) охватывает
15 программ: 10 преимущественно macOS и 5 Windows/кроссплатформенных.
Использованы официальные сайты, документация, репозитории и конкретные issues.
Аналоги не устанавливались и не сравнивались по CPU/RAM на одном устройстве.
Отдельные отзывы используются как сценарии для проверки, не как статистика.

Сохраняем прямое меню, стабильные папки, короткие подписи, локальность и явную
цель вставки. Не возвращаем поиск, создание закреплений, облако, AI, аналитику
или большой интерфейс хранения. Принятые/отложенные решения перечислены в матрице.

## Вкладка «Версия»

В исходниках добавлена шестая панель настроек:

- Версия и build читаются из Bundle запущенной копии. Отдельная QA-копия явно
  названа тестовой; отсутствующие метаданные не подменяются версией `0`.
- «О NeClip» открывает эту же панель без сети. Команда проверки в меню открывает
  её и запускает проверку по явному действию пользователя.
- Установленная версия, результат GitHub и дата последней успешной проверки
  показаны раздельно. Кэш всегда датирован и не выдаётся за новую проверку.
- Состояния «проверяем», ошибка/offline, совпадение, доступное обновление и
  локальная сборка новее опубликованной отображаются внутри окна, без NSAlert.
- Повторные нажатия не запускают параллельные запросы. Ошибка сохраняет прежний
  валидный результат и его исходную дату.
- Кэш содержит только проверенные метаданные релиза и дату в UserDefaults,
  не историю буфера, содержимое сниппетов, пароли или данные клавиатуры.

Транспорт использует ephemeral URLSession без cookies и URL cache. Redirect
отклоняется до отправки дополнительного запроса. Ответ ограничен 64 КБ при
чтении потока, а не только после загрузки; сессия отменяется при завершении
или ошибке. Тайм-аут ресурса — 15 секунд. Проверки HTTPS, точного хоста/пути,
типа JSON, версии/build, SHA-256 и адреса DMG сохранены. Открытие панели,
запуск приложения и чтение кэша не инициируют сеть.

Владельцы: `UpdateChecker.swift`, `PreferencesWindow.swift`, `AppDelegate.swift`
и точка входа проверки в `StatusBarController.swift`.

Рекомендации Apple: [Settings](https://developer.apple.com/design/human-interface-guidelines/settings),
[Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts),
[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback).
Из них использованы устойчивые панели настроек, заголовок активной панели и
контекстное сообщение вместо информационного модального окна. Это не заявление
о прочтении всех разделов Apple HIG или сертификации интерфейса Apple.

## Три оптимизации без изменения пользовательских данных

1. **Общий SHA-256 hex encoder.** `ContentDigest.swift` заменяет создание
   форматированной строки для каждого байта digest. Его используют capture и
   storage fallback; алгоритм SHA-256 и lowercase-ключи дедупликации остаются теми же.
2. **Индекс сниппетов без цепочки промежуточных массивов.** После прежней
   стабильной сортировки строки группируются одним проходом. Порядок `sortIndex/id`,
   отсутствие папки, старые orphan-метаданные и очистка состояния сохраняются.
3. **Нет повторной сортировки каждого подменю папки.** SQL уже выбирает
   ограниченную проекцию в стабильном порядке; группировка сохраняет порядок
   входа. Меню использует подготовленные строки, не сортирует их повторно.

Свойства приватности, polling, expiry паузы, восстановление pasteboard,
completion OCR, существующие лимиты и миграции не менялись ради ускорения.
Новая вкладка имеет собственную цену в коде/размере; уменьшение отдельного
участка не означает, что всё приложение стало меньше или быстрее.

## Локальные проверки

Обычная debug-сборка завершилась успешно. В исходной матрице четырёх конфигураций
(debug, strict release с обычным `-O`, ASan, TSan) выполнено 260 XCTest cases: четыре opt-in
проверки пропущены, 256 успешны, ошибок нет. Дополнительно прошли четыре Swift
Testing checks: **260 успешных проверок в каждой конфигурации**, не 264.
Локальные логи: `/tmp/neclip-111-tests.log`, `/tmp/neclip-111-strict.log`,
`/tmp/neclip-111-asan.log`, `/tmp/neclip-111-tsan.log`, `/tmp/neclip-111-build.log`.

После принятия target-only настройки и проверки её контракта повторные полные
debug/strict release запуски также дали по 260 успешных проверок без ошибок;
итоговая strict release сборка прошла. Логи:
`/tmp/neclip-111-final-debug.log`, `/tmp/neclip-111-final-release.log`,
`/tmp/neclip-111-final-build.log`. Повторный pre-commit secret scan чистый:
`/tmp/neclip-111-final-secrets.log`.

После принятия target-only `-Osize` полная release-suite повторена с тремя
opt-in benchmarks: 260 XCTest cases, один skip, ноль ошибок, плюс четыре Swift
Testing checks — **263 успешных проверки**. Логи:
`/tmp/neclip-111-target-osize-build.log` и `/tmp/neclip-111-target-osize-tests.log`.
Настройка применяется только к release-сборке NeClip; debug/ASan/TSan сборки

### Размер и скорость

Обычный stripped `-O` бинарник кандидата: **4 426 032 байта** против
**4 383 456 байт** у публичной 1.10.0: **+42 576 байт (+0,97%)**. Вкладка версии
и безопасный транспорт имеют стоимость до настройки режима сборки. Принятый
target-only режим ниже уменьшает итоговый бинарник. Все эти числа — размеры
исполняемых файлов, не DMG и не всей app bundle.

Микробенчмарк hex encoding, 50 повторов по 256 кодирований:

| Метрика | Прежний formatter | Общий encoder |
|---|---:|---:|
| Median | 3,976375 мс | 0,324750 мс |
| p95 | 4,284125 мс | 0,340542 мс |

Медиана улучшилась примерно в **12,2 раза только на кодировании digest в hex**.
Это не измерение SHA-256 целиком, пользовательской задержки вставки, запуска
или расхода памяти приложения. Отдельного доказанного коэффициента ускорения
группировки папок и меню в этом отчёте нет.

### Принятое решение по размеру сборки

Глобальный `-Osize` дал **3 800 952 байта** (−14,12% от текущего `-O`),
но **отклонён**: повторные замеры показали примерно +6% к DB snapshot
(около +0,032 мс). Уменьшение пакета не оправдало замедление общего пути.

Принят `-Osize` **только для executable target NeClip в release-конфигурации**
через `Package.swift`. GRDB остаётся с обычным speed-oriented `-O`.
Итоговая повторная сборка: **4 329 808 байт**, то есть **−96 224 байта (−2,17%)** относительно
той же версии с обычным `-O`, и **−53 648 байт (−1,22%)** относительно
публичной 1.10.0. Принятие настройки исходников не означает публикацию релиза.

Медианы трёх повторных release-запусков; время в миллисекундах:

| Метрика | Обычный `-O` | Принятый target-only `-Osize` |
|---|---:|---:|
| Snapshot median | 0,537625 | 0,530750 |
| Snapshot p95 | 0,601459 | 0,597584 |
| Clips median | 0,180417 | 0,173333 |
| Snippets median | 0,350625 | 0,343917 |
| Hex encoding median | 0,326375 | 0,326667 |

В этих микробенчмарках нет наблюдаемой регрессии DB snapshot, а hex encoding
практически одинаков. Это не доказательство ускорения native GUI, запуска,
вставки или всех рабочих нагрузок. Дополнительные повторы находятся в локальных
логах `/tmp/neclip-111-target-osize-bench-2.log` и
`/tmp/neclip-111-target-osize-bench-3.log`.

### Native GUI: проверенные сценарии и ограничения

Первоначальные обращения CUA по пути приложения завершались timeout. Повтор
через bundle ID дал доступ к изолированной QA-копии: блокер визуальной проверки
снят для следующих сценариев:

- Все шесть вкладок доступны при ширине окна 600; светлая/тёмная тема и
  минимальный размер проверены.
- Начальное «ещё не проверялась» → явное нажатие проверки → GitHub 1.10.0/build 17
  против QA 1.11.0/build 18, с понятным local-newer статусом и датой 16:30.
- «Закрыть» и ⌘W убирают окно, но QA-процесс остаётся работать.
- Повторный запуск в светлой теме показывает сохранённый результат с прежней датой.
- Переход «Основные» → «О NeClip» открывает «Версия» без нового запроса:
  сохранённая дата не меняется.

Основной агент сохранил локальный снимок `codex-shot-2026-09-07_16-30-04.png`
во временной папке macOS; снимок не включён в публикуемые файлы.
Offline, oversized-response и более новая remote-версия с кнопкой скачивания
проверены unit-тестами, **не native GUI**. Запуски используют отдельные QA-данные;
это не проверка установленного production-приложения или всех возможных сценариев.

## Что не сделано этим документом

- Публичный manifest, GitHub Release и сайт не переведены на 1.11.0.
- Не заменены `/Applications/NeClip.app` и production database.
- Не запрашиваются новые разрешения клавиатуры или доступ к пользовательскому буферу.
- Не заявлен процент общего ускорения без воспроизводимого сравнения.

Для публикации нужен отдельный release gate: точный чистый коммит, required CI,
подпись, нотарификация/stapling, Gatekeeper, независимая проверка публичного DMG
и согласованные метаданные. Для установки — отдельная безопасная процедура
с резервной копией базы; предыдущая миграция v7 требует matching pre-upgrade
database при откате на старый бинарник.
