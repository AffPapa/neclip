# NeClip 1.6.0: повторное исследование с нуля

Дата: 1 сентября 2026 года.

Этот документ не продолжает старый список автоматически. Продукты заново
разделены по задачам, текущий исходный код NeClip заново сопоставлен с каждой
идеей, а решения приняты по четырём ограничениям продукта: быстро, понятно,
локально и без обязательных разрешений.

## Профессиональная постановка

Роль: ведущий macOS product engineer, исследователь desktop-продуктов,
архитектор Swift 6/AppKit и специалист по privacy-first UX.

Задача: проверить 20 актуальных менеджеров буфера и 20 инструментов работы с
раскладкой; отделить реальные механики от маркетинга; составить ровно 100
кандидатов; оценить лучшие 20; реализовать только связный минимальный срез,
который ускоряет ежедневную работу и не добавляет аккаунт, облако, телеметрию,
AI, рекламу, Dock-иконку или неочевидное фоновое поведение.

Критерий завершения: функция не считается готовой без теста, понятного места в
интерфейсе, обновлённой карты проекта и прохождения полной локальной проверки.
Публикация и замена установленного приложения — отдельный release gate.

### Вывод по буферу

Лучшие продукты не выигрывают количеством экранов. Они уменьшают число
действий: открыл, нашёл, посмотрел, вставил. Повторяются семь сильных механик:
немедленный поиск, preview без открытия редактора, pin, ограничение хранения,
исключения приложений, одноразовое объединение и последовательная вставка.
NeClip уже закрывает пять из семи; самые дешёвые недостающие улучшения — Space
preview и одноразовое объединение следующего текстового копирования.

### Пять разных архитектур

1. Ручная конвертация выделения или последнего слова: самое предсказуемое
   действие, обычно достаточно Accessibility.
2. Автокоррекция на границе слова: требует поток клавиш, confidence, защиты
   контекстов, undo и обучения исключениям.
3. Память последней раскладки приложения: не читает текст; восстанавливает
   последний выбор при возврате в приложение.
4. Фиксированная раскладка приложения: не читает текст; при активации выбирает
   заранее закреплённый источник.
5. Раскладка физической клавиатуры: решает другой сценарий и добавляет Input
   Monitoring, поэтому для NeClip не оправдана.

NeClip уже имеет первые три архитектуры. Самое полезное недостающее дополнение
— фиксированная раскладка для конкретного приложения. Она должна иметь
приоритет над «последней использованной», срабатывать только при активации и не
мешать пользователю временно сменить язык вручную.

## Повторный аудит текущего NeClip

Исходная точка: ветка `codex/neclip-product-reset`, commit `8dd92e5`, Swift 6.2,
macOS 14+, единственная зависимость GRDB 7.11.1. Перед изменениями прошли 111
XCTest (один opt-in skip) и восемь Swift Testing checks, ошибок нет.

Уже реализованы: локальная ограниченная история, FTS/fuzzy/structured search,
pin, OCR, инспектор, сниппеты и папки, безопасные transforms, последовательная
вставка, пять переназначаемых горячих клавиш, ручная и консервативная auto
коррекция, память раскладки приложения, очистка по сроку/выходу, paste-and-delete.

Обнаруженные пробелы: preview вызывается только `⌘E`, хотя поле уже имеет hook;
нет одноразового append; нет фиксированной раскладки приложения; очистка базы
по квоте загружает все строки и удаляет по одной; список исключений clipboard
не нормализуется; нет allow-list, session-only history, reverse queue, QR и
color preview. Последние пять полезны не всем и не входят в ближайший срез.

## Выбранный срез 1.6.0

1. `Space` открывает существующий локальный preview первого результата, только
   когда строка поиска пуста; при вводе запроса пробел остаётся обычным пробелом.
2. «Объединить со следующим текстом» — одноразовое явное действие. Следующий
   допустимый текст дописывается через перевод строки к последнему незакреплённому
   тексту; картинки и отклонённые sensitive/oversized значения флаг не съедают.
3. В меню раскладки можно закрепить текущий системный источник за приложением,
   которое было активно до открытия NeClip. Правило действует при следующей
   активации, имеет приоритет над memory mode, не читает клавиши и очищается явно.
4. Byte-quota trim выполняется set-based запросом в SQLite вместо загрузки всех
   строк и цикла отдельных удалений.
5. Bundle-ID исключения нормализуются, очищаются и дедуплицируются одинаково.

Не входят: новый основной экран, облако, аккаунт, AI, фоновые network calls,
скрипты, макросы, физическая клавиатура и дополнительные системные разрешения.
