# NeClip 2.8.5 follow-up risk matrix

This re-review retains the 100 concrete baseline scenarios in [the 2.8.4 risk matrix](QA-2.8.4-RISK-MATRIX.md). It adds six delta scenarios below; this is not a claim that all baseline rows were rerun, nor that every row is a defect. Current evidence distinguishes source review, synthetic tests, and unverified native interactions.

| ID | Scenario | Expected behavior | Evidence and cause | Change / regression check | Result |
|---|---|---|---|---|---|
| R101 | Hide NeClip after screenshot encoding starts, before Save/Copy completes. | Complete the requested write/copy and return the editor from its exporting state. | Confirmed in 2.8.4 source: `window.isVisible` caused an early return after encode and before delivery/state cleanup. | Removed visibility from the delivery guard. `testExportDeliveryDoesNotDependOnEditorVisibility` locks delivery/state-cleanup code paths. | Fixed by source review and XCTest. Physical hide-during-export UI run remains unverified. P1. |
| R102 | Render 100 KB of ordinary non-token text. | Preserve all bytes and avoid a material regression. | `testLargeLiteralTemplateAndBraceHeavyTextRemainUnchanged`; synthetic render median 2.869 ms baseline / 2.851 ms candidate; p95 3.018 / 3.005 ms. | Added opt-in `testSyntheticLargeSnippetRenderLatency`; no behavior change to literal path. | Correctness test passes; measurements are local debug microbenchmarks. |
| R103 | Render 60 KB containing 20,000 unknown `{x}` sequences. | Preserve the literal text without repeatedly checking unrelated token patterns. | Baseline median 81.295 ms / p95 83.439 ms. The scan compared all token patterns after every opening brace. | Grouped token candidates by following byte; added the large-template benchmark and retained the exact-output regression test. | Candidate median 13.256 ms / p95 13.599 ms (about 6.1× lower median); XCTest, ASan and TSan renderer coverage passed. Synthetic result, not a general app speed claim. |
| R104 | Search synthetic history with 100 / 500 / 2,000 entries. | Return the requested matches without a visible latency regression. | Same in-memory SQLite fixture and benchmark on baseline/candidate. | No search code changed. | Median ms baseline → candidate: 0.496 → 0.541; 2.452 → 2.471; 9.718 → 9.828. Close results; no speedup claimed. Not a full menu/open-window benchmark. |
| R105 | Refresh synthetic menu storage projections with 200 clips and 200 snippets. | Keep database/projection reads bounded and stable. | In-memory fixture; excludes AppKit menu construction, startup, and user data. | No storage code changed. | Combined median 1.830 ms baseline / 1.870 ms candidate; sample noise is larger than this difference. |
| R106 | Use VoiceOver with a large snippet library and inspect selected state, hidden overflow, and folder navigation. | Announce the selected row and disclose where additional snippets can be found. | Source uses native list selection and combined accessibility labels; over-200 menu items direct the user to the editor. No physical VoiceOver session was performed. | No change until the assistive-technology behavior is observed. | Code-reviewed only; native VoiceOver and large-library traversal remain unverified. |
