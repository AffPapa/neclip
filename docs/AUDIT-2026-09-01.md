# NeClip deep product and code audit — 1 September 2026

Scope: current unreleased Swift tree, tests, release/security automation,
historical requirements and current competitor UX. Public 1.4.0 artifacts and
the installed application were not changed.

## Track 1 — completeness and product truth

Evidence reviewed: README, changelog, backlog, prior audits/research, source
inventory and test contracts.

Findings:

- Previously reported menu appearance, numeric controls, configurable hotkeys,
  snippet editing and Quit wiring exist in source and have contract tests.
- Current functionality had no up-to-date module map.
- Structured search was implemented but discoverable only through a tooltip.
- Public 1.4.0 metadata correctly remains separate from unreleased source.

Changes: current project map, current competitor review, native filter menu and
updated repository metadata.

## Track 2 — performance, correctness and privacy

Evidence reviewed: capture hot path, menu refresh, database reads/writes,
snippet deletion, OCR scheduling, layout event buffer and pasteboard handling.

Positive evidence:

- Capture checks pasteboard generation and processes payloads off the main
  thread.
- Menu history uses bounded summary rows without image/RTF BLOBs.
- OCR is serialized; automatic-layout tokens remain bounded in RAM.
- Temporary paste restoration uses compare-and-swap behavior.
- Layout correction fails closed in protected and unknown contexts.

Fixed findings:

- **P0:** full deletion performed one transaction/notification per snippet and
  left empty user folders. It is now one atomic clips/snippets/folders write.
- **P1:** menu refresh loaded every snippet after imports that may contain
  thousands. It now loads at most 201 rows to expose a 200-row menu projection
  and only the referenced folders.
- **P1:** item inspection showed a technical bundle identifier. It now resolves
  the local application display name.

## Track 3 — current competitive UX

Twenty clipboard managers/system histories plus layout-switcher references were
rechecked. The complete decision matrix is in `COMPETITOR-UX-2026-09-01.md`.
The selected pattern is discoverability inside the existing native control,
not additional permanent UI. Heavy boards, accounts, sync, AI, macros and
background expansion were rejected.

## Acceptance gates

- Targeted storage/menu contract tests.
- Complete test suite including realistic 1,000-item storage latency case.
- Strict Swift 6 complete-concurrency release build with warnings as errors.
- Address and thread sanitizers.
- Full-history secret scan and repository policy contracts.
- JSON parsing and `git diff --check`.
- Isolated native UI check without replacing `/Applications/NeClip.app`.
- Repeat source audit for unfinished markers, unbounded menu queries and stale
  documentation.

## Verified results

- Targeted new contracts: 3/3 passed.
- Complete suite: 111 checks executed, 110 passed and zero failed; the one
  skipped XCTest is an opt-in migration test that requires a disposable
  external database copy.
- The 10,000-row migration/1,000-item retained-history latency test passed.
- Strict release build passed with Swift 6 complete concurrency and warnings as
  errors.
- AddressSanitizer and ThreadSanitizer each passed the complete suite.
- Full-history secret scan checked 25 commits plus the publishable uncommitted
  tree and reported no detected leaks.
- All public JSON parsed; `git diff --check` and the unfinished-marker scan were
  clean.
- Isolated visual QA confirmed the unified five-tab Settings window and matched
  numeric controls. The natively attached search-menu property and actions
  compiled and are protected by repository contract tests. A programmatically
  opened `NSMenu` closes before system automation can inspect its tracking
  loop, so a real status-item click remains a manual release QA item.

`/Applications/NeClip.app`, public GitHub metadata, releases and the 1.4.0
download were not changed. These are source-quality results, not a public
release claim.
