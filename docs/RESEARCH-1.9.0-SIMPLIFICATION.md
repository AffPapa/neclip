# NeClip 1.9.0: основания упрощения

Дата проверки источников: 2026-09-06. Срез реализации: рабочая версия 1.9.0 поверх `8237e47`. Основа предыдущего исследования — [обзор 2026-09-05](RESEARCH-2026-09-05.md); здесь оставлены только решения, относящиеся к текущему упрощению.

Матрица сопоставляет документацию авторов с кодом NeClip. Это проверка описанных сценариев, а не сравнительный запуск приложений. Столбец «Решение» — инженерный вывод для NeClip, не рекомендация авторов источника. «Принято: сохранено» означает существовавшее поведение, а не новую функцию 1.9.0. Числа производительности, прохождение тестов, качество отрисовки и готовность релиза этот документ не подтверждает.

## Технические основания

| Первичный источник и конкретный контракт | Решение в NeClip 1.9.0 | Статус и причина минимализма |
| --- | --- | --- |
| [Apple: DispatchWorkItem.cancel](https://developer.apple.com/documentation/dispatch/dispatchworkitem/cancel%28%29?changes=_1): отмена предотвращает последующий запуск блока, но не прерывает уже начавшийся | `MenuSearchWork.enqueue` возвращает отменяемую задачу SQL; `StatusBarController.searchChanged` заменяет ею задачу задержки. Проверка поколения запроса остаётся на получении результата | Принято: изменено. Устаревшие запросы, ещё стоящие в очереди, пропускаются; отдельный планировщик не нужен. Отмена не выдаётся за прерывание выполняющегося SQLite-запроса |
| [Apple HIG: Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls) и [DisclosureGroup](https://developer.apple.com/documentation/swiftui/disclosuregroup?changes=_11): частые действия доступны сразу, подробности раскрываются по запросу | В общих настройках размер текста перенесён в «Дополнительно»; объяснение модификаторов и последовательной вставки — в «Работа в меню» на вкладке сочетаний. Лимит истории и длина строки остаются видимыми | Принято: изменено. Меньше постоянного текста, прежние настройки доступны. Это основание организации, а не доказательство удобства при минимальном размере окна |
| [Swift: Strings and Characters, UTF-8 Representation](https://raw.githubusercontent.com/swiftlang/swift-book/main/TSPL.docc/LanguageGuide/StringsAndCharacters.md): `utf8` представляет байты кодировки; число символов и байтов различается | `ClipboardCapturePolicy.textRejectionReason` проверяет байтовый лимит до нормализации и создания `Data(text.utf8)`; допустимый текст сохраняется целиком | Принято: изменено. Большой заведомо неподходящий текст не проходит следующие стадии. Гарантия постоянной сложности `utf8.count` из источника не следует и здесь не заявляется |
| [GRDB 7.11.1: Executing Updates, Fetching Methods, Avoiding SQL Injection](https://github.com/groue/GRDB.swift/blob/v7.11.1/README.md) ([читаемый исходник](https://raw.githubusercontent.com/groue/GRDB.swift/refs/tags/v7.11.1/README.md)): выборочные SQL-запросы и связанные параметры внутри доступа к БД | `Storage.setOCRText` обновляет OCR и размер без получения исходных BLOB в Swift; `setPinned` читает метаданные. `fetchSummaries` и `snippetQueryTail` объединяют повторяющиеся части запросов | Принято: изменено. Сохраняются параметры SQL, учёт ёмкости и транзакционный путь записи. Выбор конкретных столбцов — решение NeClip; замена GRDB или введение нового слоя хранения отложены |

Новый экран поиска не требуется; заявления Maccy о скорости не используются как benchmark NeClip |
| [Clipy: официальный репозиторий](https://github.com/Clipy/Clipy) и [release notes](https://github.com/Clipy/Clipy/releases): история с нумерацией меню, редактор сниппетов и папки | Сохранить знакомое меню; вынести одинаковое построение страниц истории и закреплённых в `MenuPagination`, не менять абсолютные номера | Принято: сохранено и объединено. Размер страниц по десять — существующий контракт NeClip, не норматив Clipy. Перенос стека и механизмов миграции другого приложения не требуется |
| [CopyQ](https://hluk.github.io/CopyQ/): найти элемент → редактировать или вставить в прежнее окно; дополнительные вкладки, команды и скрипты | Сохранить явное редактирование и цель вставки. В редакторе NeClip убрать повтор построения строк, оставив выбор по ID и защиту черновика | Принято: сохранено. Скриптовые команды и дополнительные вкладки отложены: они расширяют модель продукта, не упрощая текущий путь |
| [Paste: Search and filters](https://pasteapp.io/help/search-and-filters): печатать → уточнить по приложению/типу/времени → выбрать результат | Сохранить существующие фильтры в поисковом меню и ограниченную выдачу; общий SQL для сводок уменьшает дублирование реализации | Принято: сохранено и объединено. Дополнительные сохранённые фильтры и отдельная панель коллекций отложены. Новые фильтры в 1.9.0 не добавлены |
| [Raycast: Clipboard History](https://manual.raycast.com/clipboard-history): отдельная клавиша → поиск или фильтр типа → вставка; другие операции открываются через Actions | Сохранить прямой вход и существующие действия; объяснение модификаторов раскрывать на вкладке сочетаний. «Без ограничения по сроку» точнее описывает нулевой retention при действующих лимитах количества и объёма | Принято: сохранено, подписи уточнены. AI-команды и сетевые превью отложены: они не нужны для локальной вставки и добавляют отдельные зависимости |
| [Alfred: Snippets](https://www.alfredapp.com/help/features/snippets/): создать коллекцию и сниппет отдельными кнопками; найти по названию или ключу в viewer | Кнопка «Папка…» видима рядом с «Новый»; «Дублировать» описывает действие; подсказка поля объясняет, что ключ служит поиску в меню NeClip | Принято: изменено. Автоматическое разворачивание ключа при печати и управление курсором отложены: отдельный сценарий с новыми условиями безопасности и совместимости |
| [Pastebot](https://tapbots.com/pastebot/): быстрые номера для последних записей; подробности в preview; стек для последовательной вставки; конструктор фильтров | Сохранить имеющиеся быстрые номера, инспектор и последовательную вставку. Не добавлять новые постоянные панели в рамках упрощения | Принято: сохранено. Конструктор преобразований, Smart Pastebins и отдельное окно стека отложены: существующий ограниченный сценарий не требует их настроек и состояний |

## Как воспроизвести проверку решений

Сначала сверить контракт по ссылке и найти указанный символ в `Sources/NeClip`. Для изменяемых сайтов дата выше фиксирует момент исследования; у GRDB ссылка закреплена на версии зависимости из `Package.swift`. Для Apple использованы доступные текстовые результаты официальной документации; JavaScript-оболочка сама по себе доказательством не считалась. У Swift прочитан Markdown из официального репозитория книги.

| Изменение | Проверяемое поведение в существующих тестах |
| --- | --- |
| Отмена работы и страницы меню | `MenuWorkRegressionTests`: отменённый запрос из очереди не выполняется, следующий выполняется; границы страниц и абсолютные индексы сохраняются |
| Обработка большого текста | `TextCapturePreflightTests`: точная граница UTF-8, порядок отказа, сохранение решений для пустого и чувствительного текста |
| Запись OCR и закрепление | `ClipboardMetadataMutationTests`: исходные представления сохраняются, OCR остаётся доступен поиску, payload-столбцы не перепривязываются, отказ по ёмкости откатывается |
| Обновление редактора | `SnippetsEditorTests`: внешнее обновление сохраняет черновик; чистый редактор получает актуальные папку и закрепление; неудачная запись допускает повтор |
| Консолидация настроек | `SettingsPersistenceTests`: прежние ключи сочетаний, проверка значений, вытеснение старых записей и уведомления о раскладке |

Это указатели на проверяемые контракты, а не журнал выполненных запусков. Скорость проверяется отдельно на синтетических данных; отрисовка — в изолированном приложении при размерах настроек 600×500 и редактора 640×420, включая раскрытые блоки. Решения об уменьшении кода оцениваются по удалённому дублированию и сохранённому поведению, а не по достижению процента удаления любой ценой.
