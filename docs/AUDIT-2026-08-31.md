# NeClip deep quality cycle — 31 August 2026

This is the public engineering record for the 1.3.2 quality cycle. GitHub is
the only NeClip publication source; no separate product database, account,
telemetry service or external landing is required to understand the product.

## Professional prompt used for the cycle

Act as a combined Principal macOS/Swift Engineer, Application Security and
Privacy Engineer, Performance/Release Engineer, and Senior Product Designer
for menu-bar utilities. Audit NeClip as a local Apple-Silicon clipboard manager
with no accounts, cloud, telemetry, permanent Dock icon, or background network
traffic. Run exactly three independent read-only tracks before broad changes:

1. architecture, performance, storage and concurrency;
2. macOS APIs, privacy, permissions, update and release security;
3. menu-bar UX, onboarding, history, search, snippets, layout correction and
   accessibility.

Compare conclusions against current primary Apple and GitHub documentation and
official competitor sources. Rank findings P0/P1/P2, implement P0 and only the
P1 needed for coherence, verify every slice, and repeat the audit. GitHub is the
only public source of truth.

## Product boundary

- Local history and snippets only; no account or cloud synchronization.
- No telemetry, advertising, subscription or AI processing.

## Audit 1 — architecture and performance

### What was already correct

- Pasteboard observation is bounded to a 500 ms timer with tolerance. The main
  thread snapshots AppKit representations; hashing, decoding and database work
  run on one utility queue.
- Text, RTF, encoded image bytes, decoded image pixels and file counts have hard
  limits before expensive processing.
- GRDB serializes database access. FTS5 search reads summaries without original
  image/RTF BLOBs. History has item and 250 MB byte caps; pins survive trimming.
- OCR is local and serialized. Unknown applications and concealed/transient
  pasteboard types fail closed.

### Finding: duplicate refresh after every accepted copy

**Evidence:** `Storage.insert` posted `.neClipStorageDidChange`, then
`ClipboardMonitor` invoked a second callback that loaded the same menu snapshot
again. The old `refreshIfVisible` name was also misleading because it refreshed
when the menu was closed.

**Change:** storage change is now the only refresh source. The redundant
callback, unused notification, extra main-queue hop and settings-only history
reload were removed.

**Expected effect:** one database snapshot/model refresh instead of two per
copy, with no change to the conservative 500 ms clipboard interval.

### Finding: compiled unreachable window implementation

**Evidence:** the 846-line `ClipboardPanelController.swift` had no external
reference after the 1.3 native-menu migration.

**Change:** the missing item actions were first restored in the native menu,
then the unreachable controller was deleted. The cycle removes more source than
it adds and leaves one primary interaction model.

## Audit 2 — platform, privacy and supply chain

### What was already correct

- On macOS 15.4+, `.default` and `.ask` require the user's choice,
  `.alwaysAllow` proceeds and deny/unknown fails closed, matching
  [`NSPasteboard.AccessBehavior`](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum).
- Manual correction restores the pasteboard only through a whole-value
  compare-and-swap. Automatic correction never modifies clipboard history.
- The updater accepts only the exact GitHub Pages manifest and exact
  `AffPapa/neclip` release path. It has response, MIME, URL, version, build and
  checksum validation and never runs in the background.
- The release script preflights notarization before changing `dist`, signs
  inside-out, notarizes/staples app and DMG, mounts the exact DMG and asks
  Gatekeeper to assess the mounted app.
- The sole third-party Action was already pinned to a full commit SHA and CI
  had read-only token permissions.

### Repository hardening applied

- Enabled GitHub Immutable Releases. Future releases use GitHub's recommended
  draft -> attach all assets -> publish sequence.
- Enabled vulnerability alerts and automated Dependabot security updates.
- Added weekly SwiftPM and GitHub Actions version checks.
- Restricted workflows to GitHub-owned Actions and required full-SHA
  references at repository-policy level.
- Enabled CodeQL default setup for Swift and Actions with the local-and-remote
  threat model.
- Enabled GitHub Private Vulnerability Reporting and linked it from the
  security policy and a privacy-safe issue form.
- Protected `main` from force-push and deletion, including administrators,
  without requiring pull requests or blocking ordinary owner pushes.
- Removed the stale external homepage from GitHub metadata, made the
  repository-owned Pages endpoint canonical, improved discovery topics and
  removed the confirmed-empty Wiki.

## Audit 3 — product, menu-bar UX and accessibility

### What was already correct

- The release app is a native `NSStatusItem`, always visible in the menu bar,
  with `LSUIElement=true` and no permanent Dock icon.
- Search is the first control. Ten recent items are inline, older items are
  grouped by tens, pins and snippet folders have explicit sections, and the
  same menu contains privacy recovery, capture controls, layout commands,
  settings, manual update and quit.
- Onboarding now says that NeClip should already appear in Accessibility and
  that pressing `+` is not normally needed. Its fallback application picker
  starts in `/Applications`.

### P0 workflow gap: pins were visible but could not be created

The old panel contained pin/delete/save-as-snippet, but the active native menu
did not. This made the pin section a one-way display and made deleting one
sensitive accidental item unnecessarily hard.

### Selected minimal interaction

The native menu now has an explicit **Actions for First Result** submenu. The
action target is intentionally deterministic: the first visible result before
or after search.

- `Command-P`: pin or unpin.
- `Command-S`: save a text result as a snippet.
- `Command-Delete`: delete one result.
- `Command-Z`: restore the last individual deletion.

Snippet undo preserves identifier, folder when it still exists, keyword, pin,
usage counters and timestamps. If its folder was deleted after the item, undo
restores the snippet unfiled instead of failing or recreating a stale folder.

Global-hotkey registration failures are now shown in the menu with the exact
occupied combination and a menu-bar fallback. A full shortcut recorder remains
P2 until this simpler recovery proves insufficient.

The design follows the keyboard-first item actions documented by
[Maccy](https://github.com/p0deje/Maccy) while keeping the explicit history and
snippet hierarchy associated with [Clipy](https://github.com/Clipy/Clipy).

## Priority closure

### P0/P1 closed in this cycle

- Missing pin/delete/save-as-snippet in the active UI.
- Exact undo for snippet deletion.
- Duplicate per-copy menu refresh.
- Silent global-hotkey conflicts.
- Unreachable large-window code.
- Missing repository dependency/scanning/release-integrity policies.
- Missing private vulnerability-reporting channel and stale external homepage.

### P2 intentionally deferred

- User-recordable shortcuts.
- More keyboard layout pairs or per-app language rules.
- macOS 27-only status-item interfaces while macOS 27 is beta.
- Themes, cloud, account, telemetry, AI or a large workspace window.
