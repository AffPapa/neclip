# NeClip: immediate reuse, not a searchable archive

Status: local development after public 1.9.1; not published or installed over the public app.

## Scope and acceptance plan

Product/UX prompt: simplify NeClip to recent copies and folder snippets. Remove
all app-owned search fields and keyword editing. Keep native selection, readable
titles, folder navigation, paste and editing immediately understandable.

Swift/storage prompt: remove query parsing, filters, fuzzy ranking, callbacks,
index maintenance and unused models rather than merely hiding their controls.
Preserve payloads, permissions, privacy guards, bounded projections and undo.

QA prompt: verify upgrades and legacy import, autosave failures, menu contracts,
normal/strict/sanitizer tests and the isolated Preview. Never use the user's
production clipboard/database as test fixtures. Do not publish a local build as
a verified release.

1. Trace editor, menu, storage, onboarding and test dependencies.
2. Remove menu/editor search, keyword fields and their query-only code.
3. Add a forward migration retiring only derived indexes and triggers.
4. Update regression tests for the remaining workflows and legacy compatibility.
5. Run full debug/release/ASan/TSan suites, secret scanning and isolated UI QA.
6. Update README, backlog and project map; preserve historical release evidence.

## Implemented

- Menu opens directly on **Недавние**, without a custom text field, focus timer,
  filter menu, debounce task or queued search SQL.
- Snippets expose title, folder, pin and text, without search keys or keyword
  subtitles. Duplicate-key errors and normalizers are removed.
- Native arrows/Return select menu items; existing item callbacks, target capture,
  modifier-aware mouse paste and top-item actions remain. Space-preview and
  search-field-specific Return combinations are retired with the field.
- The controller retains only the top action item, not a duplicate quick-selection
  array. SQLite recency ties use descending IDs for stable ordering.
- Three runtime modules removed: ClipboardSearch, MenuSearchRequest, MenuSearchPage.
- Runtime Swift source is 964 lines smaller than the preceding local commit;
  tests and historical migration definitions are not counted in that reduction.
- v7 removes both FTS tables, their six triggers and keyword uniqueness index.
  Historical migrations and the inert legacy keyword column remain for safe
  compatibility. No user content tables are dropped by this migration.
- Old JSON keyword fields are ignored; export omits them. Import stays bounded,
  atomic and merge-only; repeated import does not duplicate content.
- Menu remains bounded to 100 recent/100 pinned items and 200 snippet summaries.
  Overflow is explicit: the complete snippet editor is reachable. Existing
  history values beyond the menu window are not deleted by this change.
- URL opening retains the shared safe HTTP(S) resolver; obsolete email/color/code
  search classification is removed.
- Onboarding describes selection rather than search. README describes this
  source workflow as unreleased; historical release records remain intact.

## Verification

- Debug: 234 XCTest cases, 2 optional skips, 0 failures; 4 Swift Testing checks.
- Strict release: same result, complete concurrency and warnings-as-errors.
- AddressSanitizer and ThreadSanitizer: same complete test result for each.
- Total successful checks per configuration: 236. The lower count than the
  previous search-enabled branch reflects retired feature tests, not skipped
  privacy or data-integrity checks.
- New regression coverage: legacy keyword JSON, conflict-free edits/export,
  v6-style populated FTS retirement, content/image/folder/pin/usage preservation,
  reopen and undo. Existing v2 migration and 10,000-row migration checks pass.
- Secret scan: detector canaries, publishable tree, 51 HEAD commits and two
  side-ref-only commits clean before this change is committed.
- `git diff --check`: clean.
- Isolated QA database was backed up before v7; seven snippets and one folder
  remained after migration. Public application and database were not migrated.

Native UI QA: the rebuilt Preview shows no editor search or keyword field and
no keyword subtitles. Selecting another row updates the body correctly. The
history menu exposes Недавние and folder submenus with no search input; the
dedicated snippet menu exposes folders and nine-item quick access without keys.
Settings and Quit have active targets. Seven existing QA snippets remain available.
The first UI attachment timed out; one scoped Preview restart restored the
existing connection. A fallback Screen Recording helper was blocked before
execution; no permission was granted and no fallback screenshot was taken.
The existing native UI tool provided the editor screenshot successfully.
Production hotkeys are occupied by the installed app, so this QA used the
Preview's application-menu commands rather than claiming global-hotkey or
live target-app paste verification. No production clipboard content was read.

## Release / rollback boundary

No GitHub release, public site, update feed, signing identity or installed
`/Applications/NeClip.app` changed. Before a future production install, take a
consistent database backup while the app is stopped. Old binaries require FTS
and must not be run against a v7 database: rollback needs the matching database
backup as well as the old app. QA retains its private pre-migration SQLite copy.

Removing derived search indexes stops their per-copy/per-edit work. No arbitrary
latency multiplier is claimed without a controlled benchmark.
